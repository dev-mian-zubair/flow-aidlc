Read `.flow/playbook.md`, then verify that all Build slices in `worklog/<PI-NNN>/shape/slices.md` are checked complete in `worklog/<PI-NNN>/progress.md` before proceeding; enter the Ship phase by loading `.flow/steps/ship/branch-hardening.md` first (dispatching the `pr-review-toolkit` agents from `config.yaml → review.branch_hardening` on the branch diff) and pausing at the `branch-hardening` checkpoint for `/flow-approve`; upon approval load `.flow/steps/ship/learnings.md` (the pre-PR learnings retro) and complete it; then load `.flow/steps/ship/open-pr.md` (invoking `superpowers:finishing-a-development-branch`), run the pre-PR sanity checks, and pause at the `open-pr` checkpoint for `/flow-approve` before performing `OPEN_PR`; append final entries to `worklog/<PI-NNN>/journal.md`. The Flow **terminates at the open PR** — it does not merge. Merge, required checks + approvals, ticket close, and any serialization-lock release are owned by the team on the host (branch protection on the base branch is authoritative). See `knowledge/decisions/0010-ship-ends-at-open-pr.md`.
